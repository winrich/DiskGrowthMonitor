Size accounting comparison

This table answers a common question: why is the size counted here smaller than the used space shown by Explorer? "Counted here" is the sum of deduplicated logical file sizes accumulated per directory, while "volume used" is the number of allocated clusters reported by the volume. The latter includes parts that belong to no directory, so the former is usually a few percent smaller. This is an accounting difference, not evidence of missed directories.

VolumeVolume capacityVolume usedCounted hereDifferenceDifference %
C: 341.68 GB 333.45 GB 328.20 GB +5.25 GB 1.58%

The difference comes from three places, none of which is a missed scan: 1) NTFS metadata and MFT reserved areas ($MFT, directory indexes $I30, $Secure:$SDS and so on) belong to no directory, yet the system counts them as volume used; 2) excluded or skipped directories are not counted at all (see the "Skip list"); 3) with hardlink dedup disabled, the same physical data reached through several directories is counted more than once, and the counted size can then be larger than volume used, making the difference negative.

Metric notes

  • Size: the accumulated byte count of a directory subtree, including all descendant directories and files; the same physical data behind hardlinks is counted once, under the first path it appears at.
  • Change = current size − previous size; Change % = change ÷ previous size. When the previous size is 0 or absent, the percentage shows NEW.
  • Per-directory changes overlap by nature: a parent's change already includes its children's, so nested paths in the rankings are expected. Tick "Deepest level only" to see the finest grained growth points.
  • The growth ranking starts at the first level of subdirectories; for the scan root's own change see "Scan root comparison".
  • Counted size vs. volume used: the former is the sum of deduplicated logical file sizes, the latter the number of allocated clusters (including NTFS metadata and reserved areas that belong to no directory), so the former is usually a few percent smaller. See "Size accounting comparison".
  • Excluded directories (the default list and --exclude) and skipped directories are not counted towards any ancestor's accumulated size.
